Knowledge Bridge API 文档
========================

Base URL: http://127.0.0.1:8111


HMAC 签名（机器到机器接口）
---------------------------

需要签名的接口必须携带三个请求头：

  X-KB-RequestId    请求唯一标识
  X-KB-Timestamp    Unix 毫秒时间戳
  X-KB-Signature    Base64(HMAC-SHA256(requestId + timestamp + SHA256Hex(body), sharedSecret))

签名计算流程：
  1. bodyHash = SHA-256(requestBody) → 十六进制字符串
  2. signatureContent = requestId + timestamp + bodyHash
  3. hmac = HMAC-SHA256(signatureContent, sharedSecret)
  4. signature = Base64(hmac)

时间戳容差：5 分钟（300000ms）

1. 查询知识证据包  [需要 HMAC]
========================================================================

POST /api/v1/query

请求体：
{
  "requestId": "uuid-string",          // 必填，请求唯一标识
  "userId": "user-001",                // 必填，用户 ID
  "chatId": "chat-001",               // 可选，群聊 ID
  "sessionKey": "session-key",         // 可选，会话标识
  "messageId": "msg-001",             // 可选，消息 ID
  "question": "如何部署 sing-box？",    // 必填，用户问题
  "channelType": "feishu",            // 可选，渠道类型
  "isGroup": false,                    // 是否群聊
  "flags": {                           // 可选，查询控制标志
    "strictKbOnly": false,             // true = 只基于知识库回答（KB_ONLY）
    "needCitation": false              // 是否需要引用来源
  }
}

响应体：
{
  "requestId": "uuid-string",
  "route": "KB_PLUS_LLM",             // KB_ONLY | KB_PLUS_LLM | LLM_ONLY
  "allowModelSupplement": true,        // 是否允许模型补充回答
  "sources": [                         // 知识证据列表
    {
      "dataset": "kb_qa",
      "title": "sing-box 部署 FAQ",
      "content": "...",
      "score": 0.92,
      "metadata": {
        "topic": "sing-box",
        "reviewStatus": "APPROVED"
      }
    }
  ],
  "instructions": [                    // 回答约束指令，注入 LLM 上下文
    "优先依据sources回答",
    "不要编造未在sources中出现的事实",
    "如sources不足可补充但需标注"
  ],
  "retrievalQuality": {                // 检索质量摘要
    "hitCount": 3,                     // 返回证据条数
    "confidence": "HIGH",              // HIGH | MEDIUM | LOW
    "truncated": false,                // 是否发生截断
    "originalHitCount": 3              // 截断前命中数
  }
}

2. 自动候选评估  [需要 HMAC]
========================================================================

POST /api/v1/ingest/candidate

请求体：
{
  "requestId": "uuid-string",          // 必填
  "userId": "user-001",                // 必填
  "chatId": "chat-001",               // 可选
  "messageIds": ["msg-001"],           // 可选
  "content": "消息内容...",             // 必填
  "sourceType": "FEISHU_CHAT",        // 必填，FEISHU_CHAT | MARKDOWN | TUTORIAL | NOTE | ATTACHMENT
  "attachments": [                     // 可选
    {
      "name": "file.pdf",
      "url": "https://...",
      "mimeType": "application/pdf"
    }
  ]
}

响应体：
{
  "requestId": "uuid-string",
  "worthy": true,                      // 是否值得沉淀
  "reason": "内容值得沉淀",             // 判定原因
  "taskId": 42,                        // worthy=true 时返回入库任务 ID
  "duplicate": false                   // 是否内容重复
}

3. 手动入库
========================================================================

POST /api/v1/ingest/manual

请求体：
{
  "requestId": "uuid-string",          // 必填
  "userId": "user-001",                // 必填
  "chatId": null,                      // 可选
  "messageIds": null,                  // 可选
  "content": "# Markdown 内容...",     // 必填
  "sourceType": "MARKDOWN",           // 必填，MARKDOWN | TUTORIAL | NOTE | FEISHU_CHAT | ATTACHMENT
  "attachments": [],                   // 可选
  "force": false                       // 是否强制跳过去重
}

响应体：
{
  "requestId": "uuid-string",
  "taskId": 43,
  "status": "RECEIVED",
  "duplicate": false
}

  "processedGuideKey": "guide/2026-05-04/...-guide.md",
  "processedQaKey": "qa/2026-05-04/...-qa.md",
  "errorMessage": null,
  "createdAt": "2026-05-04T16:00:00Z",
  "updatedAt": "2026-05-04T16:01:00Z"

404 — taskId 不存在

5. 入库任务列表
========================================================================

GET /api/v1/ingest/tasks?page=1&size=20&status=COMPLETED&reviewStatus=CANDIDATE

参数：
  page          页码，默认 1
  size          每页大小，默认 20
  status        可选过滤，RECEIVED | RAW_STORED | PROCESSING | COMPLETED | FAILED | DISABLED
  reviewStatus  可选过滤，CANDIDATE | APPROVED | REJECTED

响应：MyBatis-Plus 分页结构

7. 审核接口
========================================================================

POST /api/v1/review/approve
  请求体：{"taskId": 42, "reviewer": "admin", "comment": "ok"}
  响应体：{"message": "审核通过"}

POST /api/v1/review/reject
  请求体：{"taskId": 42, "reviewer": "admin", "comment": "质量不达标"}
  响应体：{"message": "审核拒绝"}

POST /api/v1/review/batch
  请求体：
  {
    "reviewer": "admin",
    "items": [
      {"taskId": 42, "action": "APPROVE", "comment": "ok"},
      {"taskId": 43, "action": "REJECT", "comment": "不合格"}
    ]
  }

GET /api/v1/review/pending?page=1&size=20&sourceType=MARKDOWN
  参数：page, size, sourceType（可选）

GET /api/v1/review/{taskId}
  404 — taskId 不存在

8. 文档管理接口
========================================================================

GET /api/v1/documents?page=1&size=20&status=COMPLETED&knowledgeType=QA

POST /api/v1/document/{documentId}/enable
  响应体：{"message": "文档已启用"}
